# Pets for Vets API

The Go backend that replaces PocketBase. Go standard library for HTTP,
PostgreSQL for data, and hand-written SQL turned into Go code by
[sqlc](https://sqlc.dev).

## Running it

From the repository root:

```sh
colima start              # Docker runtime, once per boot
docker-compose up -d      # Postgres on localhost:5432
cd api && go run ./cmd/server   # API on localhost:8080 (applies migrations)
npm run dev               # in another terminal: Vue on localhost:5173
```

Vite forwards every `/api/...` request to the Go server (see `server.proxy` in
`vite.config.ts`). The browser only ever talks to one origin, so the session
cookie just works and there is no CORS setup.

A dev account's login is in `.dev-login` at the repo root (git-ignored).

## Layout

```
api/
├── cmd/server/main.go          entry point: config, DB pool, migrations, start HTTP
├── internal/
│   ├── db/
│   │   ├── migrations/*.sql    the schema, as numbered goose migrations
│   │   ├── queries/*.sql       every query the app runs, hand-written
│   │   └── *.go                GENERATED by sqlc from the two folders above
│   └── httpapi/
│       ├── server.go           route table + middleware
│       ├── auth.go             register / login / logout / sessions
│       ├── pets.go             pet endpoints
│       └── json.go             small helpers for JSON in/out
├── sqlc.yaml                   sqlc settings
└── go.mod / go.sum             dependencies (like composer.json / composer.lock)
```

`internal/` is a Go rule, not just a convention: code in it can only be
imported from inside `api/`.

## Coming from PHP

| PHP | Here |
|---|---|
| Apache/nginx runs `index.php` once per request | `main.go` starts one long-running process; each request runs in its own goroutine (a cheap thread) |
| `new PDO(...)` per request | One `pgxpool.Pool`, created at startup and shared by all requests |
| `$stmt = $pdo->prepare('... WHERE id = ?')` | Same idea: `$1, $2` placeholders in `queries/*.sql`. Values never get pasted into the SQL string |
| `$stmt->fetch(PDO::FETCH_ASSOC)` returns an array | sqlc generates a struct per query, e.g. `ListPetsByOwnerRow`; a wrong column name fails at `sqlc generate`, not at runtime |
| `session_start()` + `$_SESSION` | `startSession` + the `sessions` table. We control where sessions live |
| `password_hash()` / `password_verify()` | `bcrypt.GenerateFromPassword` / `bcrypt.CompareHashAndPassword`, same `$2a$...` format |
| `json_encode($array)` | `writeJSON(w, status, value)`; the `json:"name"` tags on structs set the keys |
| Exceptions + `try/catch` | Functions return an `error` as their last value; you check `if err != nil` immediately |
| `composer require` | `go get`, then `go mod tidy` |
| PHP-CS-Fixer | `gofmt -w .` (one official style, no config) |

## How a request flows

`GET /api/pets` with a session cookie:

1. **Router** (`server.go`): `"GET /api/pets"` matches `s.requireUser(s.handleListPets)`.
2. **`requireUser`** (`auth.go`): reads the `session` cookie, SHA-256 hashes it,
   runs `GetSessionUser` (a JOIN of `sessions` and `users` that skips expired
   rows). No row means 401. Otherwise it calls the handler with the `User`.
3. **`handleListPets`** (`pets.go`): runs `ListPetsByOwner(user.ID)`: one SQL
   query with `JOIN species` and `LEFT JOIN breeds`, filtered by `owner_id`.
   That `WHERE owner_id = $1` is the access rule PocketBase used to enforce for
   you.
4. Rows are copied into `petResponse` structs (the public JSON shape, kept
   separate from the table layout) and sent with `writeJSON`.

## Adding a query or endpoint

1. Schema change? Add a new migration: `goose -dir internal/db/migrations create add_something sql`.
   Never edit a migration that has already run; add a new one.
2. Write the query in `internal/db/queries/*.sql` with a `-- name: Foo :one|:many|:exec` comment.
3. `sqlc generate`: you now have `s.queries.Foo(ctx, ...)`.
4. Write a handler in `internal/httpapi/` and add its route in `server.go`.
5. Add a function to `src/api/*.ts` in the frontend.

## Useful commands

```sh
sqlc generate                         # after changing any .sql file
go vet ./... && gofmt -l .            # static checks / unformatted files
goose -dir internal/db/migrations postgres "$DATABASE_URL" status
docker-compose exec db psql -U petsforvets   # SQL shell
docker-compose down -v                # wipe the database completely
```

## Security notes

- **Passwords**: bcrypt hashes only. Login gives the same error and takes the
  same time whether the email exists or not.
- **Sessions**: the cookie holds a random 128-bit token; the database stores
  only its SHA-256 hash. The cookie is `HttpOnly` (unreadable by JavaScript),
  `SameSite=Lax`, and `Secure` when `COOKIE_SECURE=true` (set that in production).
- **CSRF**: `http.NewCrossOriginProtection` rejects state-changing requests
  from other sites.
- **SQL injection**: impossible by construction. All values are parameters.

## Endpoints

All except register/login/logout need the session cookie.

| Method | Path | Notes |
|---|---|---|
| POST | `/api/auth/register` | `{email, password, name, surname}` → 201 user, logs you in |
| POST | `/api/auth/login` | `{email, password}` → 200 user |
| POST | `/api/auth/logout` | → 204 |
| GET | `/api/auth/me` | → the logged-in user, or 401 |
| GET | `/api/pets` | your pets, with species and breed |
| POST | `/api/pets` | create → 201 pet |
| GET | `/api/pets/{id}` | → pet, or 404 (also for other people's pets) |
| PUT | `/api/pets/{id}` | full update → 200 pet |
| DELETE | `/api/pets/{id}` | → 204 |
| GET | `/api/species` | all species |
| GET | `/api/breeds` | all breeds, generic first |
| PUT | `/api/auth/me/app-mode` | `{app_mode}`; `clinicTeam` only for vets (403 otherwise) |
| POST | `/api/auth/change-password` | `{current_password, new_password}` → 204, logs out everywhere |
| GET | `/api/pets/{id}/prescriptions` | a pet's repeat prescriptions |
| GET | `/api/pets/{id}/prescription-requests` | a pet's requests, newest first |
| POST | `/api/prescriptions/{id}/requests` | request a repeat → 201; 409 if one is already open |
| DELETE | `/api/prescription-requests/{id}` | cancel → 204; 409 unless Pending |

## Dev data

Prescriptions are written by clinic staff, and the clinic side doesn't exist
yet. To get sample prescriptions for the dev account's pets:

```sh
docker-compose exec -T db psql -U petsforvets < api/dev/seed_dev_data.sql
```
